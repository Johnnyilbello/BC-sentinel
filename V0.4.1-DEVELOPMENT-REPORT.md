# BC Sentinel v0.4.1 Beta — Development Report

## Executive summary

BC Sentinel v0.4.1 implements **Behavioral Correlation Engine 2.0** on top of the field-validated v0.4.0 Reputation + Network Intelligence baseline.

The previous v0.4.0 Windows acceptance supplied from the target PC passed all critical checks, including ETW, Authenticode, native watchdog, NTFS reparse handling and network process attribution. Because v0.4.1 changes the correlation layer and acceptance harness, a new Windows freeze run is still required for this release.

## 1. Baseline gate

Source baseline: `BC_Sentinel_v0_4_Beta_Reputation_Network_Intelligence.zip`.

- **152/152 tests PASS**.

After v0.4.1:

- Python `compileall`: **PASS**.

## 2. Behavioral Correlation Engine 2.0

`sentinel/correlation_engine.py` was upgraded from mostly same-PID contextual scoring to a sequence-aware engine.

### Time and ancestry model

- default correlation window: **45 seconds**;
- bounded per-PID history;
- bounded global history reserved for PID-less persistence linking;
- parent/child ancestry participates in event-family retrieval;
- process-generation-aware incident IDs reduce PID-reuse ambiguity.

### Ordered sequences

The engine can now distinguish ordered chains such as:

`Office → encoded PowerShell → network → payload write → child execution`

and:

`network → persistence`

Ordering matters. A later encoded script does not retroactively create an encoded-script → network sequence for an earlier connection.

### Cross-PID payload execution

A file written by a parent/ancestor process can be matched to a child executable path. This produces stronger evidence than the previous generic "recent file write" heuristic.

### Persistence convergence

Local fallback persistence events now enter the same `on_security_event()` pipeline as process/file/network telemetry. PID-less persistence can be linked to a recent executable only when the persistence value directly references that observed path/name.

## 3. False-positive control

Evidence is grouped into semantic families. Repeated observations in the same family do not stack linearly: the strongest family member wins, then cross-family convergence receives bounded diminishing bonuses.

High-volume legitimate clients such as browsers, sync tools and developer clients retain conservative network gates. Generic cache-write + HTTPS behavior does not create a behavioral alert by itself.

Endpoint reputation remains independent context. A malicious endpoint can corroborate a behavioral chain but its reputation score is not blindly double-counted in the correlation delta.

## 4. Explainability payload

Each correlation result can now expose:

- `score_delta`;
- `total_score`;
- `confidence`;
- `severity`;
- `incident_id`;
- process `chain`;
- ordered `stages`;
- `evidence_families`;
- bounded human-readable `sequence`;
- reasons.

The Activity detail panel stores and renders the new context without redesigning the existing Premium UI.

## 5. Thread safety

Correlation event history is now read/written under `RLock`. A parallel-event regression submits 200 events across eight worker threads and verifies bounded valid results without corruption or exceptions.

## 6. Packaging fix from Windows field acceptance

The v0.4.0 field run initially exposed missing ETW/service imports when installing only `requirements.txt`.

v0.4.1 fixes this by adding Windows-conditional top-level dependencies:

- `pywintrace==0.2.0`;
- `pywin32>=311`.

The existing split requirement files remain available for bootstrap/build compatibility.

## 7. Acceptance harness

`tools/windows_acceptance.py` now includes `behavioral-correlation-v2`, a fully synthetic in-memory probe. It verifies that a harmless synthetic Office → PowerShell → network → file-write → child-execution sequence produces the expected cross-PID evidence and incident metadata.

No process is launched, terminated or quarantined by this synthetic probe.

## 8. Performance

New tool: `tools/correlation_benchmark.py`.

Final synthetic run:

- events: **10,000**;
- synthetic process identities: **200**;
- elapsed: **4.689 s**;
- throughput: **~2,132.56 events/s**;
- correlation window: **45 s**.

A hot-path optimization avoids scanning global history for ordinary process/file/network events; global lookup is reserved for PID-less persistence linking.

## 9. Security boundary

v0.4.1 does **not** introduce autonomous response authority. It does not:

- kill/suspend processes;
- block packets;
- delete files;
- auto-quarantine solely from behavioral correlation;
- claim kernel/minifilter/WFP enforcement.

Those actions require the upcoming protected service architecture and stronger response invariants.
